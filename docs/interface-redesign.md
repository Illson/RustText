# Редизайн интерфейса RustText

Согласованный вариант: компактный «Пульт логов» с меню «Файл», «Инструменты» и «Поиск». Реализация сохраняет существующие команды, горячие клавиши, форматы файлов и сессии.

## Критерии приёмки

- Открытие, сохранение, выбор кодировки и история находятся в меню «Файл»; отдельной строки кнопок открытия и сохранения нет.
- «Инструменты» содержит форматирование JSON, замену, перенос, масштаб и доступные для текущего режима операции с логом.
- Под вкладками лога одна строка: имя файла, режим только для чтения, пауза/возобновление автообновления, независимое следование за концом и состояние автообновления.
- Поиск располагается под текстом; результаты открывают нужное совпадение. Для текста сохраняются поиск по вкладкам и замена, для логов — порционное чтение результатов и отмена.
- Навигация лога и метаданные остаются снизу. Несохранённые изменения, ошибки чтения/записи, отмена обрезки и подтверждение физического удаления остаются доступны.
- Основные действия доступны при минимальном размере окна 760 × 350 и в отдельном тестовом профиле.
- В тексте и логах широкая полоса прокрутки: дорожка 16 px, ползунок 12 px, при наведении и перетаскивании 14 px.

## План

1. Обновить меню, палитру, вкладки и строку состояния документа.
2. Собрать управление логом в одну строку, переместить редкие операции в инструменты и поиск вниз.
3. Адаптировать текстовый поиск к нижней панели с результатами; проверить переходы и ограничения замены.
4. Выполнить целевые тесты, форматирование, полный набор тестов, Clippy и ручные сценарии на копиях файлов; опубликовать ветку и PR, проверить Actions.

## Риски

- Потеря фокуса при переходе из меню в поиск или редактор: проверять горячие клавиши и выбор результата.
- Переполнение небольшого окна: ограничивать высоту результатов, сохранять место для текста и доступность команд.
- Смешение автообновления и следования за концом: сохранять независимые переключатели и явный статус.
- Физическая обрезка остаётся операцией с подтверждением и полной резервной копией; перенос команды не меняет алгоритм записи.

## Проверки

Проверено на Windows 11 x64 с Rust 1.100.0 и CMake 4.5.0:

- `cargo test --locked search::`: 9 целевых тестов прошли. Новые тесты проверяют ограничение списка 100 результатами, общий счётчик, номера строк и байтовые диапазоны Unicode.
- `cargo test --locked`: после совмещения с актуальной основной веткой прошли 107 модульных тестов и тест Windows GUI subsystem; `cargo fmt --all -- --check` и `cargo clippy --locked --all-targets -- -D warnings` проходят.
- `cargo build --locked`: приложение собрано и запущено с отдельным `LOCALAPPDATA`, синтетическим логом 71,5 МБ и копиями текстовых файлов.
- В окне проверены нижние панели поиска, список текстовых совпадений, переход по результату лога, меню инструментов, пауза при дописывании и возобновление со следованием за концом. Проверены ввод процента обрезки, отдельное окончательное подтверждение и отмена до записи. После перезапуска восстановилась вкладка лога.
- При клиентской области 760 × 350 проверены обе строки поиска, единая строка лога, доступность навигации и широкая прокрутка. В тексте проверены переход ко второму совпадению, замена выбранного вхождения и сохранение через «Файл → Сохранить»; результат дополнительно прочитан с диска.

Алгоритмы чтения, индексирования, ротации и физической обрезки не менялись. Замеры на 10/20 ГиБ и отдельная проверка Windows 10 в этой задаче не повторялись.

## Проверка после объединения с PR №7

- В Windows x64 прошли проверка форматирования, сборка, Clippy с запретом предупреждений, 132 модульных теста и тест Windows GUI subsystem. Тесты поиска проверяют частичный подсчёт по лимиту, отмену, предел размера документа, список из 100 результатов и байтовые диапазоны Unicode.
- В отдельном профиле поиск по синтетическому тексту насчитал 117 совпадений и показал первые 100. Щелчок по третьему результату выбрал строку 3, а `F3` перевёл выделение на строку 4.
- В синтетическом логе на 52,5 МиБ дописали последние байты символа UTF-8. Кнопка «Ещё» стала доступна после обновления размера файла. Повторный поиск нашёл символ, а выбор результата открыл последнюю строку.
