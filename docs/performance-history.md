Сравниваем две ревизии в одной серии [парных замеров](performance.md). В истории храним дату, обе ревизии, сценарий, окружение, медианы, диапазоны отношений внутри пар и ссылку на сырой результат, если он опубликован.

## 25.11.2026 — выпуск 2.8.0

Сравнили `v2.7.1` (`e055329`) и [кандидат 2.8.0](https://github.com/Illson/RustText/commit/ba5ad53c0dc6bc8be6e9855a882043519e0e9ce8) после слияния #125–#129. Windows 11 Pro x64 22621, Ryzen 7 5800X3D, .NET SDK 11.0.100, PowerShell 7.6.9, Release Native AOT. Обе версии запускались по очереди на отдельном неактивном рабочем столе с временными профилями.

[Полный отчёт штатного стенда](performance-runs/2026-11-24-caret-standard.md) · [Сырые наблюдения, SHA и хеши входов](performance-runs/2026-11-24-caret-standard.json)

Дополнительно сравнили **набор текста и простой сфокусированного редактора** в Avalonia Headless 12.1.6 со Skia, Release JIT без tiered compilation, на той же машине. В каждом из 12 новых процессов открыли черновик из 4 000 строк, прогрели редактор 100 вводами, восстановили исходный текст и выдержали 8 с простоя. Затем подали 500 событий `KeyTextInput` (четыре «ж» и LF, 30 событий/с). После прогона сверили весь текст, 4 101 строку и положение курсора. У кандидата проверили, что анимация включена; системный интервал мигания — 530 мс. Максимальное отставание подачи от расписания — 5,32 мс. Порядок версий чередовали.

| Метрика Headless | До | С анимацией | Отношение [мин.–макс.] |
| --- | ---: | ---: | ---: |
| Выполнение вызова ввода, p50 | 7,85 мс | 5,95 мс | 0,740 [0,623–0,849] |
| Выполнение вызова ввода, p95 | 10,10 мс | 9,76 мс | 1,009 [0,813–1,061] |
| CPU процесса за 500 событий | 273,44 мс | 421,88 мс | 1,229 [0,818–5,286] |
| Управляемые выделения за 500 событий | 67,22 МиБ | 66,60 МиБ | 0,991 [0,987–0,994] |
| CPU процесса за 8 с простоя | 23,44 мс | 62,50 мс | — |
| Управляемые выделения за 8 с простоя | 0,26 МиБ | 1,74 МиБ | 6,785 [6,346–7,196] |

p50 и p95 рассчитаны сначала внутри каждого прогона, затем по шести парам. Вызов Headless включает диспетчер и отрисовку Skia; это не задержка до появления символа на мониторе. Сигнал регрессии есть в **управляемых выделениях в простое** — около 1,49 МиБ дополнительно за 8 с, не рост удерживаемой памяти. У CPU набора диапазон пересёк `1,0`; для CPU простоя отношение не рассчитывается из-за нулевого среза в одной базовой попытке. По этой серии нельзя переносить цифры Headless на активное окно Native AOT.

Повтор на новом неактивном рабочем столе, шесть пар в обратном порядке и с паузой 1,2 с, подтвердил рост выделений: 0,037 → 0,246 МиБ, медиана парного отношения 6,982 [6,163–7,608]. С такой короткой паузой точности среза CPU недостаточно: медиана обеих версий равна нулю.

[Сырые наблюдения набора и простоя](performance-runs/2026-11-24-caret-headless.json)

Стенд замера: [CaretPerformanceProbe.cs](../tools/Performance/Caret/CaretPerformanceProbe.cs), [headless.ps1](../tools/Performance/Caret/headless.ps1) и [repeat-idle.ps1](../tools/Performance/Caret/repeat-idle.ps1). Их SHA-256 совпадают с хешами в JSON. Для повтора исходной серии выполните из корня репозитория в PowerShell 7 на Windows:

```powershell
$run = Join-Path $env:TEMP ("RustText-caret-" + [guid]::NewGuid())
New-Item -ItemType Directory -Path "$run/tools", "$run/tmp" | Out-Null
Copy-Item tools/Performance/Caret/* "$run/tools"
& "$run/tools/headless.ps1"   # -CheckOnly для короткой проверки
& "$run/tools/repeat-idle.ps1"   # 6 пар по 1,2 с на тех же сборках
```

Наблюдения сохраняются в `$run/headless-observations` и `$run/repeat-idle`. После сохранения результатов временный каталог можно удалить.

### После исправления расхода памяти в простое

На том же стенде сравнили `7640751` → `5495454`: шесть пар с чередованием порядка, плавный курсор включён в обеих версиях. При системном интервале мигания 530 мс и тайм-ауте 5 с медиана временных управляемых выделений за 8 с простоя снизилась **с 1,72 до 0,49 МиБ**. Снижение во всех шести парах; медиана отношения после/до — 0,282 [0,265–0,320]. Теперь при мигании меняется только прозрачность курсора, а по системному тайм-ауту таймер останавливается.

[Наблюдения простоя по парам](performance-runs/2026-11-24-caret-idle-fix.json). Для повтора используйте `CaretPerformanceProbe.cs` на указанных ревизиях с `RUSTTEXT_CARET_BENCH_APP=candidate` для **обеих** сборок: так стенд проверяет наличие анимации. После 8 с простоя все прогоны проверили ещё 500 вводов, 4 101 строку и конечное положение курсора.

Выделения в простое не равны росту занятой ОЗУ. Отдельный тест убирает сфокусированный редактор из открытого окна и проверяет через слабые ссылки, что сборщик мусора освобождает слой курсора и документ. Длительный рост рабочего набора процесса этим тестом не измерялся.

Сравнение разных приложений не является точкой истории RustText. Алгоритмы реализованы на коде RustText без копирования исходников NetText.

- Применимые к Avalonia изменения: пакетный подсчёт разделителей, поиск по байтам с безопасным отсевом и переиспользованием буферов, операции над диапазонами в редакторе, форматирование JSON без промежуточного дерева на простом входе и экономное открытие текста.
- Быстрые пути сохраняют кодировки и смещения, CR/LF/CRLF, смешанные переводы строк, отмену, границы снимка лога и проверку внешних правок. Ограниченный фильтр regex применяется только при доказанном обязательном литерале; остальные выражения обрабатывает .NET.
- Выигрыш от Win32/GDI, Scintilla и статической компоновки его редактора не переносится без смены графического стека. В RustText не менялись Avalonia, пакеты и параметры Native AOT.
